## Migration

Oui, migration additive locale : `2026_10_02_120000_add_conversation_context_to_ai_conversations`. Elle ajoute la colonne nullable `conversation_context` à `ai_conversations`; le cast Laravel chiffre le tableau. Le contenu est borné à des références opaques, type/source/tour/horodatage et scope tenant/user/client ; aucun contenu clinique ou texte patient. `down()` retire la colonne ajoutée. Elle s’est exécutée via les tests isolés `RefreshDatabase` seulement. **Aiven n’a pas été modifié.** La migration doit suivre le processus de revue et de livraison autorisé avant activation du code en environnement partagé.

## Invariants maintenus

Laravel reste autorité d’identité, permissions, sélection, visibilité et données. SafetyPolicy passe avant outils. Tous les outils métier réutilisés sont read-only et reconstruisent `PatientContextFactory`. Aucun accès direct provider/base, note clinique, brouillon, réponse brute, score privé, autre patient, secret ou prompt système. `about_my_data` ne produit pas de dump. Mémoire v0.8 demeure distincte et explicitement contrôlée. Aucun changement des permissions v1.0.

## Recette à effectuer séparément

Le test local ne valide pas le schéma distant, le déploiement Render, l’exécution browser, la concurrence MySQL, les paramètres effectifs du flag ou le comportement UI en production. Une recette Render par l’utilisateur demeure requise avant d’affirmer le fonctionnement réel v1.1 sur Render.
